# 工作原理

DouDou 是纯静态网站：读图、抠图、出图、编辑、导出全部在浏览器里完成，没有服务器，图片不上传。

## 整体

1. **读图**：HEIC 先转换；超过 30 MB 或像素超过 4000 万的直接拒绝；缩到最长边 1024 像素以内。「假透明」的棋盘格背景会被识别并改成真透明。
2. **判断输入类型**，走不同的路径（见下）。
3. **出图**在后台线程里算，页面不会卡住。
4. **格子表格是唯一的数据**：图纸、色卡、颗数、下载都从这张表现算，所以色卡和格子永远一致。

## 三种输入

| 类型 | 怎么判断 | 怎么处理 |
|---|---|---|
| 像素画 | 颜色跳变都落在等距（或近似等距）的网格线上 | 识别出原来的格距和相位，一格一豆还原；只做色号匹配和轻微去噪 |
| 平涂图（卡通、贴纸） | 相隔一颗豆的两点颜色要么相同要么突变，渐变很少 | 按图里已有的颜色聚类后配色号；自带描边就不再描 |
| 照片 | 其他 | 先保边平滑，再按色系分层，每个色系挑几级明暗相近的色号 |

配色号用接近人眼感受的 Oklab 颜色空间计算；有颜色的地方不会被配成灰豆，接近黑白的颜色固定配黑、白豆。

## 清理

- 零碎的一两颗杂色并进旁边的色块，眼睛、高光这类小而对比强的细节保留
- 色块边缘的尖刺、多余的拐角、长短乱跳的台阶按直线或弧线理顺
- 眼睛、眉毛这类小色块按原图的面积和形状重新落格
- 只用了极少几颗的颜色换成图里最接近的颜色，不用为两三颗单买一包

## 移除背景

纯色背景从边缘往里去除；复杂背景用 U²-Netp 模型（约 4 MB，Apache-2.0）在浏览器里运行，第一次用时下载一次。没认出主体时保留背景。

## 尺寸规则

豆板只用三种：**52×52、78×78、104×104**（2.6 mm 豆），钉子有几排就能放几颗。

| 图案最长边 | 放进 |
|---|---|
| ≤ 52 | 52×52 豆板 |
| 53 – 78 | 78×78 豆板 |
| 79 – 104 | 104×104 豆板 |
| > 104 | 几块 104×104 板拼，横 ⌈宽 / 104⌉ × 竖 ⌈高 / 104⌉ 块，最大 5×5 |

- 任何图案都放进能装下它的最小豆板，居中。生成的、图纸库的、收藏的、导入的都一样
- 「自适应」：像素画按 1:1；其他图按细节能保住多少挑最小的那块板
- 「自定义」：图案按比例放进输入的宽 × 高
- 编辑时画到豆板外，豆板自动扩大：还放得进标准板就换大一号；放不下就往画出去的那一边加整块 104 板
- 实物大小按每颗 2.6 mm 算

## 图纸

- 每格写色号，细线分格；每 10 颗一条粗线；四边坐标从 1 开始
- 多块板时：板和板之间是更粗的接缝线，上方写列号 1 2 3、左边写行号 A B C，每块板叫 A1、A2、B1…，坐标和粗线在每块板里重新数
- 底部色卡：每个色号一张，写明颗数，按用量排序
- 下载的 PNG 里用文本块存了一份格子表格，拖回网站就能接着编辑；大图下载成压缩包：总览 + 每块板一张

## 图纸自动检查

每张生成的图纸都过一遍程序检查：

| 编号 | 检查什么 |
|---|---|
| A1 | 图纸画出整块豆板，按尺寸规则取能装下图案的最小一块 |
| A2 | 主体四周留出安全边距（保留背景、占满整板的除外） |
| B1 / B2 | 只用合法的 MARD 色号或空格 |
| B4 | 颜色数不超过上限 |
| B5 | 每个颜色至少用 3 颗 |
| C5 / C6 | 色卡颗数合计等于格子数，并按用量排序 |
| D5 / D7 | 孤立杂点少于 5%，没有和主体分离的小块 |

## 编辑与性能

- 编辑只重画改动的格子，大图上画一笔也在几十毫秒内完成
- 出图、算颜色上限等重计算放在后台线程
- 撤销重做保存的是整张表格的快照
